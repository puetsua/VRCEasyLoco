# Releasing EasyLoco

Maintainer-only procedure for cutting a new `vrchat.puetsuaworkshop.easyloco` release. Mirrors the ButtonWizard package.

## Steps

1. Bump `version` in `package.json`.
2. Run `.github/workflows/release.yaml` manually (workflow_dispatch).
3. Workflow publishes a zip + `.unitypackage`.
4. Notify the `puetsua/vrc-stuff` VPM listing via repository dispatch.

## What ships

The workflow's `Make Package Folder` step ships **every root entry except dotfiles and the exclusion list**. On that list: `AGENTS.md`, `Tests`, and this folder — `Documentation~` holds the artwork sources and this procedure, none of which belongs in a user's project.

A `~` suffix is not what keeps a folder out: it only stops Unity importing it, and the release copies root entries by name. `Documentation~` ships unless it is on the list, which is why it is.

Anything else added at the root lands in the zip and `.unitypackage`, so a new repo-only root entry has to be added to the exclusion list or it ships.

## Changelog

Release notes are generated by [git-cliff](https://git-cliff.org) from commit subjects since the previous tag; `.github/cliff.toml` holds the grouping rules.

Subjects are grouped by leading verb, so write them in the imperative:

- `Add ...` / `Fix ...` / `Remove ...` → their own sections
- everything else → `Changed`
- `chore:` / `ci:`-prefixed commits are excluded

Preview what a release would say before running the workflow:

```
git cliff --config .github/cliff.toml --unreleased --tag <version> --strip all
```
